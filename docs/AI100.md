# AI100 development and run workspace

AI100 uses `D:\Projects\MechoFly` as its canonical development and run
directory. Its working tree tracks `main` from
`https://github.com/yaelkroy/MechoFly.git`, while a machine-local profile selects
Firefly Prism at runtime.

## Initial setup or safe synchronization

From a copy of this repository, run Windows PowerShell 5.1:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\tools\Setup-AI100-MechoFly.ps1 -Launch
```

On each run, the setup script:

1. clones `origin/main` when the target is absent or empty;
2. otherwise requires the canonical origin, a clean working tree, and branch
   `main`, then fetches and fast-forwards to `origin/main`;
3. proves local `HEAD` exactly matches `origin/main`;
4. writes `%LOCALAPPDATA%\MechoFly\runtime-profile.json` with Firefly selected
   and `live_hardware_authority` set to `NONE`;
5. verifies repository identity, builds x64, and runs the deterministic safety
   self-test through a waited GUI-subsystem process;
6. checks the receipt for `PASS`, unchanged live state, Drosophila as repository
   default, and Firefly availability;
7. removes only recognized shortcut names from the previous fly application on
   the user and public desktops; and
8. creates current-user **Start MechoFly**, **Stop MechoFly**, and **Emergency
   Stop MechoFly** shortcuts.

Omit `-Launch` when the goal is synchronization and verification only:

```powershell
.\tools\Setup-AI100-MechoFly.ps1
```

## Refusal conditions

The script stops without replacing content if the target is a nonempty
non-repository directory, the checkout has an unexpected origin, the worktree
is dirty, the current branch is not `main`, or a fast-forward is impossible.
Resolve the condition deliberately and rerun it.

The workflow does not delete any project directory, rewrite history, install
drivers, configure WSL, or connect the stimulation preview to live hardware.
Generated binaries and self-test receipts stay in ignored local directories.
